## The data

Both fixtures were generated by really running Level 7 Project 03's
`BattleService` — not hand-typed. `scripts/generate_fixtures.py` is an
author-only provenance tool; you don't need to run it.

`data/deep_dive_battles.json` — ~500 battles of **one fixed matchup**
(same hero class vs. same monster, every battle). Shape:

```json
{"hero_class": "...", "monster": "...", "matchup": "...",
 "battles": [{"winner": "hero"|"monster", "rounds": N, "gold_earned": N}, ...]}
```

`data/tournament_history.csv` — 45 independent tournament *runs* across
every hero-class/monster combination (several dozen battles each, already
aggregated to one row per run). Columns:

```text
run_id, hero_class, monster, matchup, battles, hero_wins, hero_win_rate, avg_rounds, avg_gold
```

Each `_variant` file has the same shape but comes from a genuinely
different tournament configuration — different numbers, and for the
history file, a different answer to "which class is most balanced."
Hardcoded answers that happen to match the primary fixture will fail on
the variant.

## Your task

Open `task.py` and implement all eight functions.

**NumPy, on the deep-dive matchup:**

```python
def load_battle_arrays(path: Path) -> tuple[np.ndarray, np.ndarray, np.ndarray]: ...
def deep_dive_stats(wins: np.ndarray, rounds: np.ndarray) -> dict[str, float | int]: ...
def battle_matrix_summary(wins: np.ndarray, rounds: np.ndarray) -> dict[str, float]: ...
```

**Pandas, on the tournament history:**

```python
def load_tournament_history(path: Path) -> pd.DataFrame: ...
def win_rate_by_class(df: pd.DataFrame) -> dict[str, float]: ...
def rank_monsters(df: pd.DataFrame) -> list[str]: ...
def unfavorable_matchups(df: pd.DataFrame) -> list[str]: ...
def balance_conclusions(df: pd.DataFrame) -> dict[str, str]: ...
```

**Synthesis:**

```python
def build_final_report(deep_dive_path: Path, history_path: Path) -> dict[str, object]: ...
```

Each function's docstring has the exact contract. Notes worth reading
before you start:

- **Use NumPy for every statistic in `deep_dive_stats`** — mean, median,
  std, the 90th percentile, and the boolean-mask-based quick-win count —
  not only for building the array. `np.percentile` and `np.quantile` are
  both accepted.
- **`battle_matrix_summary` must really use `axis=0`** on a real 2D
  array — the point is the axis-aggregation idiom, not just the right
  two numbers computed separately.
- **`win_rate_by_class`, `rank_monsters`, and `unfavorable_matchups` must
  use pandas' `groupby`.** A `.unique()` loop can produce similar numbers,
  but `groupby` is what this task exists to reactivate.
- **`balance_conclusions` uses only plain groupby aggregation compared
  against 0.5** — no correlation, no inferential statistics.
- **`build_final_report` should call the functions above**, not
  recompute anything by hand.

## Questions this answers

1. Which monster is hardest, by average hero win rate?
2. Which hero class is, on average, closest to a 50/50 fight?
3. Which matchup is the most one-sided?
4. In the deep-dive matchup: are quick hero wins (2 rounds or fewer)
   common or rare?

No correlation, no statistical tests, no confidence intervals, no ML —
just groupby, comparisons, and arithmetic against 0.5.
